- Create a new component "Tooltip" it will be used to replace all tooltips which are created with "title" with an enhanced version
- Design and interaction should be the same as tooltip from openui5 - see sap/ui/core/tooltip in "../openui5" folder
    - it is a popover which opens on top/bottom of elements mainly, you may reuse the existing popover if it is easy
    - the interaction differs from the native tooltip because it also opens on focus and on longpress, together with the classic hover open
    - specifics about the user interaction should be same as openui5, but we may reduce some specifics if they make the implementation much better
    - visual design must be exactly as the one in openui5
- I imagine we should have a component <ui5-tooltip> which every other component, like the <ui5-button> can use inside its template to show the enhanced tooltip. API should be easy and clean
- The opener can be directly the component root focus dom ref (e.g. <ui5-button>) or an html element inside it. It should be defined as property of the <ui5-tooltip>, e.g. opener, look how such associations are already implemented in the framework
- Use the <ui5-button> and <ui5-title> as first sample controls which upgrade to the new tooltip
- Make APIs and all implementation to be in sync with how ui5-webcomponents work. They are quite different than openui5, so do not copy code and implementation details directly, but rethink them and implement specifically for webcomponents
    - one such detail is that in webcomponents we can render the tooltip on place before it is opened, so we can refer with aria-describedby directly to it, which replaces the invisible tooltip from openui5. That also means to use the role="tooltip" on the tooltip and to point to it with aria-describedby. Test if this works
    - another specific is that the lifecycle of the controls is easier to handle in webcomponents, so we don't need TooltipEnablement at all.
    - another specific is that in webcomponents it should be easier to directly use the <ui5-popover> and maybe we don't need any posititioning logic in the tooltip itself, if we take it directly from popover
    - overstyling of the popover is also easier
    - we most likely don't need "late text setting before open" in webcomponents. So try to avoid it - set the text simply and directly in the component template
- make also all needed test pages, demo pages and automated tests
- use the browser to test as much as needed, iterate as long as needed until you have a clean implementation, as simple as possible and a working tooltip for button and title
