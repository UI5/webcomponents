1 — Scrollable container (overflow: auto) —
The IM sits inside an auto-height div inside a fixed-size scroll box. A classic scrollbar (~15px) steals width from the container, which can push the IM across a breakpoint and trigger the oscillation this fix targets.
2 — Clipping container (overflow: hidden) —
No scrollbar at all — the container clips its content. The IM's available width equals the frame width exactly, with no scrollbar side-effect. Useful baseline to confirm no spurious re-sizing.
3 — Flex column parent (align-items: stretch) —
IM is a direct child of a flex column with stretch alignment — the layout algorithm sets the IM's width, not the IM itself. Common in full-page app shells and panel bodies.
4 — Flex row: sidebar + flex:1 IM —
A fixed 60px sidebar sits left of the IM, which takes flex:1. The IM's available width is always (frame width − 60px). Tests that the IM responds correctly to fractional flex-derived widths near breakpoints.
5 — CSS grid cell (60px sidebar + 1fr IM) —
IM occupies a 1fr grid column next to a fixed 60px sidebar. The grid engine computes the IM's width fractionally — tests that ResizeObserver picks up grid-driven size changes correctly.
6 — Padded parent (24px padding, box-sizing: border-box) —
The frame has 24px padding on all sides. The IM's offsetWidth is (frame width − 48px). Tests that padding on an ancestor does not confuse the ResizeObserver or cause the IM to pick a breakpoint based on the wrong width.
7 — Height-constrained: IM fills width:100% height:100% —
IM stretches to fill its container completely. When the container is too short for the current illustration, the IM downgrades to a smaller media size. Mirrors how IM behaves inside a ui5-dialog content area.
