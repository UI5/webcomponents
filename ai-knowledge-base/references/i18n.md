# Internationalization

Every user-visible or screen-reader-audible string comes from the message bundle — ARIA labels,
announcements, and tooltips included. Nothing in the build, lint, or CI catches a hardcoded English
string; review is the only guard.

Do not confuse this with `packages/localization`: that is a separate package for CLDR, calendars,
and date formatting, not UI strings, and nothing in the pipeline below applies to it.

## The pipeline

One `.properties` file feeds two independent outputs — the typed English defaults compiled into the
package, and the per-locale JSON assets fetched at runtime. Adding a key produces the first only.
Root `yarn generate` runs the package's `wc-dev generate`, which runs both branches:
`build.i18n.defaultsjs` writes `i18n-defaults.ts`, `build.i18n.json` writes the locale JSON assets.

```
src/i18n/messagebundle.properties  <- you edit this
  |- build.i18n.defaultsjs -> src/generated/i18n/i18n-defaults.ts   English fallback, typed constants
  |- build.i18n.json       -> dist/generated/assets/i18n/messagebundle_<locale>.json
                              registered by src/generated/json-imports/i18n.ts, via src/Assets.js only
```

`src/generated` is gitignored. When the default language is `en` the defaults
generator merges `messagebundle.properties` with `messagebundle_en.properties`, the translated file
winning.

The dev-server watch rebuilds defaults only, and only on `messagebundle.properties` — never locale
files, never the JSON assets. That is why "I added a key
and nothing happened".
Locale files come from the SAP translation pipeline; add your key to the default bundle only.

## 1. Add the key

```properties
# messagebundle.properties
#XACT: ARIA announcement for the Button Badge with value 1 - "{0} item"
BUTTON_BADGE_ONE_ITEM={0} item

#XACT: ARIA announcement for the Button Badge with value more than 1 - "{0} items"
BUTTON_BADGE_MANY_ITEMS={0} items
```

Every new key carries an annotation comment. Translators never see the rendered UI, so the comment
is the only context they get; without it they guess at the grammatical role and ship a wrong
translation. Nothing enforces it. Some keys have none, and three use a non-standard prefix — `#ACC:`
on `BUTTON_ROLE_DESCRIPTION` and `LINK_ROLE_DESCRIPTION`, `#FLD:` on
`DYNAMIC_DATE_RANGE_EMPTY_SELECTED_TEXT`. Those are recent one-off mistakes, not an older
convention the `#X...` codes replaced — the `#X...` codes have been in this file since it was
created. Do not copy them.

The full set of SAP text-type codes is larger than what this repo uses, and nothing in this repo
documents it. The codes actually in use, most common first: `#XACT` ARIA text and announcements,
`#XFLD` field label, `#XTOL` tooltip, `#XBUT` button text, `#XTXT` general text, `#XTIT` title or
heading, `#XMSG` message, `#XLNK` link text, `#XCKL` checkbox.

Placeholders are `{0}`, `{1}`, positional, passed to `getText` in order. No ICU plural syntax —
plurals are separate keys, as above.

```properties
# messagebundle.properties
#XACT: ARIA announcement for the position of the list items in an entire list
LIST_ITEM_POSITION=List item {0} of {1}
```

## 2. Name the key

`SCREAMING_SNAKE_CASE`, prefixed with the component name — one namespace per package:
`BUTTON_ARIA_TYPE_ACCEPT`, `COLORPALETTE_CONTAINER_LABEL`, `DATEPICKER_OPEN_ICON_TITLE`.

Reuse the unprefixed shared keys rather than re-declaring one behind a component prefix:
`ACC_STATE_REQUIRED`, `DELETE`, `SELECT_OPTIONS`, `VALUE_STATE_*`. `TOKEN_ARIA_DELETE=Delete`
sitting next to the shared `DELETE=Delete` is an existing instance of exactly what not to add.

The reverse also holds: never point at another component's key even when the English is identical,
because the translations diverge. Four separate keys render the English word "Close" —
`EXPANDABLE_TEXT_CLOSE`, `NOTIFICATION_LIST_ITEM_CLOSE_BTN_TITLE`, `USER_MENU_CLOSE_BUTTON_TXT`,
`USER_SETTINGS_DIALOG_CLOSE_BUTTON_TEXT` — each translated for its own grammatical context.


## 3. Use it in the component

Pick the access form first:

- **A component class** — the `@i18n` decorator. The default; use it unless one of the next two applies.
- **A bundle name known only at runtime, or one fetched in `onDefine()`** — `getI18nBundle(pkg)`.
- **A plain utility with no class to hang it on** — `new I18nBundle(pkg)`.

`i18nBundle` is a **static** class member: `Button.i18nBundle`, never `this.i18nBundle`.

```ts
import {
	BUTTON_BADGE_ONE_ITEM,
} from "./generated/i18n/i18n-defaults.js";

@customElement({
	tag: "ui5-button",
	formAssociated: true,
	languageAware: true,

@i18n("@ui5/webcomponents")
static i18nBundle: I18nBundle;

return Button.i18nBundle.getText(BUTTON_BADGE_ONE_ITEM, badgeEffectiveText);
```

`languageAware: true` is required — without it the text resolves once and goes stale on language
switch.

The bundle name is the `name` field of that package's `package.json`, character for character:
`@ui5/webcomponents` for `main`, `@ui5/webcomponents-fiori` for `fiori`, `@ui5/webcomponents-ai`
for `ai`. The generator reads that field and registers every locale loader under it, so a mismatch
raises no error — the bundle quietly resolves to the English defaults, and the only symptom is a
console warning blaming a missing `Assets.js` import.

The `getI18nBundle` cases in the tree are dynamic icon-collection bundles resolved at runtime
(`Icon`, `AvatarBadge` in `main`) and a fixed bundle fetched in `onDefine()` (the `ai` package's
`TextArea`, `WritingAssistant`, `Versioning`). `CustomAnnouncement` is the `new I18nBundle(pkg)`
case. `getText` also accepts a raw string key, but always pass the generated constant.

## Testing

Assert against the bundle, never an English literal — `getText` when the string has placeholders,
`defaultText` when it is static:

```tsx
import { FORM_GROUP_ACCESSIBLE_NAME } from "../../src/generated/i18n/i18n-defaults.js";

	.should("have.attr", "aria-label", Form.i18nBundle.getText(FORM_GROUP_ACCESSIBLE_NAME, "1"));
```

```tsx
btnText: MESSAGE_STRIP_CLOSE_BUTTON_INFORMATION.defaultText,
```

To test a non-default locale, import the asset bundle in the spec:

```tsx
import "../../src/Assets.js";
```

Without that import only the default language is loaded, and the locale switch silently does
nothing — `Assets.ts` is what pulls in the generated `registerI18nLoader` calls that fetch the
locale JSON.
