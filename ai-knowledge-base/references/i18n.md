# Internationalisation

Every user-visible or screen-reader-audible string comes from the message bundle — ARIA labels,
announcements, and tooltips included. Nothing in the build, lint, or CI catches a hardcoded English
string; review is the only guard.

`packages/localization` is CLDR, calendars, and date formatting — not UI strings.

## The pipeline

Two independent halves; adding a key covers only the first. Root `yarn generate` runs the package's
`wc-dev generate`, which runs both branches.

```
src/i18n/messagebundle.properties  <- you edit this
  |- build.i18n.defaultsjs -> src/generated/i18n/i18n-defaults.ts   English fallback, typed constants
  |- build.i18n.json       -> dist/generated/assets/i18n/messagebundle_<locale>.json
                              registered by src/generated/json-imports/i18n.ts, via src/Assets.js only
```

The build targets that drive this are `build.i18n.defaultsjs` (writes `i18n-defaults.ts`) and
`build.i18n.json` (writes the locale JSON assets).

`src/generated` is gitignored. When the default language is `en` the defaults
generator merges `messagebundle.properties` with `messagebundle_en.properties`, the translated file
winning.

The dev-server watch rebuilds defaults only, and only on `messagebundle.properties` — never locale
files, never the JSON assets. That is why "I added a key
and nothing happened".
Locale files come from the SAP translation pipeline; add your key to the default bundle only.

## 1. Add the key

```properties
# messagebundle.properties
#XACT: ARIA announcement for the Button Badge with value 1 - "{0} item"
BUTTON_BADGE_ONE_ITEM={0} item

#XACT: ARIA announcement for the Button Badge with value more than 1 - "{0} items"
BUTTON_BADGE_MANY_ITEMS={0} items
```

Every new key carries an annotation comment; it is the only context translators get. Nothing
enforces it, and a few legacy outliers have none or use a non-standard prefix (two keys use `#ACC:`,
one uses `#FLD:`). Do not copy those.

The codes, most common first: `#XACT` ARIA text and announcements, `#XFLD` field label, `#XTOL`
tooltip, `#XBUT` button text, `#XTXT` general text, `#XTIT` title or heading, `#XMSG` message,
`#XLNK` link text, `#XCKL` checkbox.

Placeholders are `{0}`, `{1}`, positional, passed to `getText` in order. No ICU plural syntax —
plurals are separate keys, as above.

```properties
# messagebundle.properties
#XACT: ARIA announcement for the position of the list items in an entire list
LIST_ITEM_POSITION=List item {0} of {1}
```

## 2. Name it

`SCREAMING_SNAKE_CASE`, prefixed with the component name — one namespace per package:
`BUTTON_ARIA_TYPE_ACCEPT`, `COLORPALETTE_CONTAINER_LABEL`, `DATEPICKER_OPEN_ICON_TITLE`.

Never duplicate a generic key under a new prefix; reuse the unprefixed shared ones:
`ACC_STATE_REQUIRED`, `DELETE`, `SELECT_OPTIONS`, `VALUE_STATE_*`.
Never reuse another component's key even if the English matches — translations diverge by context.

## 3. Add the generated constant

If the dev server is not watching, prefer running `yarn generate` — the real `i18n-defaults.ts` is
minified onto two lines, so a hand-edit is fragile. If you must edit by hand, add the entry to
`src/generated/i18n/i18n-defaults.ts` and append the name to the `export {...}` list at the bottom,
so type-checking and tests pass. Keep `defaultText` byte-identical to the properties value.

```ts
// i18n-defaults.ts
const BUTTON_BADGE_ONE_ITEM: I18nText = {key: "BUTTON_BADGE_ONE_ITEM", defaultText: "{0} item"};
```

## 4. Use it in the component

`i18nBundle` is a **static** class member: `Button.i18nBundle`, never `this.i18nBundle`.

```ts
import {
	BUTTON_BADGE_ONE_ITEM,
} from "./generated/i18n/i18n-defaults.js";

@customElement({
	tag: "ui5-button",
	formAssociated: true,
	languageAware: true,

@i18n("@ui5/webcomponents")
static i18nBundle: I18nBundle;

return Button.i18nBundle.getText(BUTTON_BADGE_ONE_ITEM, badgeEffectiveText);
```

`languageAware: true` is required — without it the text resolves once and goes stale on language
switch. The bundle name is the package: `@ui5/webcomponents` for `main`,
`@ui5/webcomponents-fiori` for `fiori`.

For a component class, always use the `@i18n` decorator. The `getI18nBundle` function form is for
cases where the class isn't the natural owner: dynamic icon bundles resolved at runtime (`Icon`,
`AvatarBadge` in `main`), or a fixed bundle fetched in `onDefine()` (the `ai` package's `TextArea`,
`WritingAssistant`, `Versioning`). A plain utility with no class can construct `new I18nBundle(pkg)`
directly (`CustomAnnouncement`). `getText` also accepts a raw string key, but always pass the
generated constant.

## Testing

Assert against the bundle, never an English literal — `getText` when the string has placeholders,
`defaultText` when it is static:

```tsx
import { FORM_GROUP_ACCESSIBLE_NAME } from "../../src/generated/i18n/i18n-defaults.js";

	.should("have.attr", "aria-label", Form.i18nBundle.getText(FORM_GROUP_ACCESSIBLE_NAME, "1"));
```

```tsx
btnText: MESSAGE_STRIP_CLOSE_BUTTON_INFORMATION.defaultText,
```

To test a non-default locale, import the asset bundle in the spec:

```tsx
import "../../src/Assets.js";
```

Without that import only the default language is loaded, and the locale switch silently does
nothing — `Assets.ts` is what pulls in the generated `registerI18nLoader` calls that fetch the
locale JSON.
